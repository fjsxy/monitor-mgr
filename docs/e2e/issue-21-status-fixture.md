# #21 status fixture 条件更新与剩余分层增量验收

本 v2 仅更正重复 ID 的层级说明；22行用例、20个剩余键与实施边界完全不变。原 v1 发布于实现前，本修订回读后继续；本地同正文保存为 `docs/e2e/issue-21-status-fixture.md`。不改产品代码、固定 Operator、超时、就绪/PVC断言、UID/RV/namespace/ledger保护或中央207/104键集。Ginkgo/UT70%/Helm依用户确认仅适用于后续开发。

C11 原 U05/U06 两项及 REG 81Q 已实际通过，均保留，不重复执行。原 REG 首个K失败/22未执行及原始422记录保持失败；私有记录未保存原JSONPatch输入，因此不宣称已证明原422的服务器内部原因。已证问题是明确的 status replace 被传输层转为JSONPatch，原子条件失败可能得到不能按标准Conflict处理的通用422。修复只为明确validated status replace保留原生条件PUT，保留当前归属/UID/RV检查与API的UID不可变、RV条件；其余PATCH原样，不笼统放行422或unknown。

现有 `--focus` 按variant过滤，剩余两项 PROJECTION013 的 K 和一项 SOURCE007 的 B 各自与已过 Q 同 ID。新增最小 `--focus-layer K B` 与variant过滤相交，list/run一致，只筛实际派发，完整104seed与未选择not_run保留；部分执行仍不得通过完整gate。新候选只执行下表20项K/B；新两项Host回归单独记，不添加中央键。每项保存真实source/原receipt/层级/cleanup；本机、CI与历史来源分开报告。
