# exporter 配套 ServiceMonitor，并以实例创建用户标记采集归属

2026-10-21 用户确认：同一集群允许平台与用户创建的观测实例共存，创建实例时记录实例创建用户。exporter 的配套 ServiceMonitor 在配置下发时由平台创建，保存草稿不写入集群；平台复用 Operator 为 exporter 生成的 Service，随 exporter 更新、删除配套 ServiceMonitor，并在 exporter 页面展示配套配置，以保持部署与采集配置的一致关系。

ServiceMonitor 的 `metadata.labels["monitor-mgr.io/user-id"]` 由平台填写，值为实例创建用户的稳定 user ID。创建关系固定，不随发布操作人、集群所属用户或集群归属转移改变；管理员创建的实例记录管理员自身的 user ID。选择创建关系是为了在同一集群内区分不同用户创建的实例，集群归属不能代替这一关系。

Agent 提供按用户关联 exporter 的快捷配置，默认使用 Agent 实例创建用户的 user ID，投影为原生 `serviceMonitorSelector`，并展示目标用户。保留现有标签配置与匹配预览；跨 namespace 关联同时配置相应 namespace 范围。管理员编辑已有 Agent 时不因当前登录用户变化而改变快捷配置的关联目标。

用户进一步确认：平台管理员创建的实例禁止普通用户修改。实例访问仍以既有集群权限为前提，实例变更还需检查这一限制；保护覆盖 exporter 与 collector，以及草稿编辑、配置下发、期望运行状态调整、删除和相关重试、取消操作。页面、后端请求入口与后台任务派发前均须遵守，不以 ServiceMonitor labels 代替平台授权判断。已经发送的请求继续只读核验真实结果，不因后续失权回滚或重放。此规则修订 ADR0007 与 ADR0009 中单纯继承集群权限的实例变更边界。

实例创建时记录并固定创建用户及其当时角色，按创建时的管理员身份保护实例。管理员后来降为普通用户，其先前以管理员身份创建的实例仍受保护；普通用户后来升为管理员，不改变旧实例的创建身份。当前操作者是否有权变更仍按其当前有效身份判断。

历史实例无法确定创建时角色时，默认禁止普通用户修改，由管理员明确确认后才开放相应管理权限。保留角色未知的历史事实，权限确认独立记录，不用账号当前角色倒推或补造历史创建角色。

已有实例从可靠的创建记录补齐实例创建用户，无法核实的记录标记为未知，不以集群所属用户或首次发布用户代替。已有 exporter 在下一次明确配置下发时补建 ServiceMonitor，不在后台自动改变集群。

exporter 已创建而 ServiceMonitor 创建失败时，保留 exporter，展示下发未完成及失败步骤，由人工重试补齐。请求结果不明确时进入结果待确认，先核验再决定后续操作。两份资源分别保留已确认身份和执行进度，配套 ServiceMonitor 沿用既有同名冲突、不接管和资源身份校验原则。

对应规格：[exporter 配套 ServiceMonitor、实例创建归属与管理员实例保护规格 #23](https://github.com/fjsxy/monitor-mgr/issues/23)。实现任务拆分另行确认；本决策与已发布规格记录产品边界，不表示功能已实现或验收通过。
