# 草稿显式发布，并保持集群资源的归属边界

一期将配置草稿和发布版本分别持久化；保存草稿不会改变集群，只有明确的配置下发操作才发布指定版本。页面分别呈现保存结果、下发结果和 CR 运行状态，使用户能够判断配置所处阶段，并为失败恢复保留依据。

平台管理由自身创建的 CR。下发遇到同名已有资源时明确报冲突，不自动接管；通过 kubectl 等途径修改这些 CR 时显示配置漂移，由用户主动重新下发，不自动覆盖外部修改。具体的资源身份校验、重试、删除与恢复规则见 [确定配置发布、漂移与删除状态机](https://github.com/fjsxy/monitor-mgr/issues/8#issuecomment-6142918240)。
