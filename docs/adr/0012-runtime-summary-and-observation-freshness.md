# 运行摘要与下发结果分开，不展示 Operator 状态报告

一期呈现组件运行摘要、可用数量、观测新鲜度及下发结果，用户明确不需要 Operator 状态报告；所选 CR 的 conditions 与 generation 也不能严格绑定某次发布，因此不将它们包装成当前发布版本已核实生效的回执。

平台保留“CR 已写入”与组件运行情况两个结论，读取失败、过期或重启尚未重新观察时显示当前未知，并单独保留历史观测，以避免旧成功状态掩盖当前无法确认的情况。具体规则见 [确定状态同步、过期标记与故障展示契约](https://github.com/fjsxy/monitor-mgr/issues/9#issuecomment-6149704214)。

2026-10-16 页面评审将“部分可用”合并到“未就绪”：未满足全部期望 Pod 的运行中实例统一显示“未就绪”，仍保留实际可用/期望 Pod 数和故障原因。挂起、停用、无匹配与当前未知继续分别表达；运行状态筛选采用同一分类。
