## 先确定执行什么

| 类型 | 目标数量 | 实际验证边界 | 进入 CI 的理由 |

| UT | 18 | 17 个后端规则/接口契约场景，1 个测试工具场景；不需要 Kubernetes | 快速验证授权、事务、配置、状态与协议；同一规则不反复部署环境 |
| E2E | 10 | 9 个通过 HTTP 驱动真实平台 Pod/Operator/Kubernetes 的场景，1 个真实浏览器流程 | 验证替身无法证明的 API/RBAC、调谐、workload、PVC 和恢复结果 |

UT 在本仓库指无需 Kubernetes 的本地测试：优先直接调用 Go 应用/领域入口，Kubernetes adapter 使用受控替身；只有协议专项保留本地真实 HTTP/Kitex/SQLite。不会把真实集群才能证明的结果写成 UT 通过。构建、格式、生成一致性属于 CI 检查，不增加第三种测试类型。

28 是实施的业务场景数，不与旧的 207 个参数展开子例作等比例比较。合并必须减少重复环境、重复入口和等价组合；不能只把旧的 115 个 Go It 和 254 项工具自测套进 28 个名字，内部继续整套运行。

## UT：保留什么、怎么合并

## E2E：需要集群的全部真实运行

一次运行自动准备两套独占 kind：control 为 1 control-plane + 2 workers，用于 DaemonSet 和分片；data 为 1 个可调度节点，用于验证跨集群目标选择。构建一次镜像、安装一次 Operator/CRD 和存储依赖，各 case 使用独立 namespace、平台 Helm release/数据卷和资源名，不依赖前例残留。平台与需部署的组件通过仓库 Helm charts 部署；预检、故障注入和测试资源由测试工具管理。

版本沿用现有 `source-lock.json`，本轮不扩大 Kubernetes/Operator 版本矩阵。集群/Operator/存储/测试 Secret 准备就绪属于公共前置，不再独立计一个 case。E2E 工具负责显式 kubeconfig/context、创建、等待 Ready、日志保存和按原身份清理；不借用当前用户集群，不手工改默认 context。全局故障、平台重建与存储操作串行。

每行一个 Ginkgo `It`，一个完整纵向场景；任何必要步骤失败，整行失败，报告定位到失败的 `By`。启动失败是环境失败，不能跳过后宣布通过。

| Retain/Delete 分别与每个动作穷举成独立 case | E2E-05 两个反向混合策略 Agent，串起缩 shards、挂起、恢复、删除；默认 Retain/Retain 在 E2E-04 | whenScaled/whenDeleted 不会互换；两种策略的真实 PVC 结果都检查 |
| 账号、字段校验、版本来源在 HTTP、直接 RPC、浏览器反复验证 | 规则归 UT；9 个 API E2E 验证真实集群；直接 RPC 只保留授权/编解码专项；浏览器只保留一条流程 | 后端不能绕过授权、页面关键操作可完成；不重复全部字段矩阵 |
| 每种异常 metadata 都真实等待约 10 秒 | UT-15 直接检查解析/截断结果，仅一个代表 RPC 做实际预算计时 | 不丢失预算规则和真实 RPC 限时证明 |
| 同一 Q 场景先被全量 Go 跑，再为 58 个收据键重跑 | CI 的 UT 只执行一次，E2E 也只执行一遍 10 个场景 | 用 Ginkgo 场景报告直接判断，不再做第二轮相同断言 |
| 254 项工具自测和多层收据/导出协议成为产品 case 清单主体 | 简化工具协议后，UT-18 只验证缺例/假通过、错误来源、错误清理三组风险；旧框架专有分支随旧框架退出 | 测试结论仍可信，清理不误伤；不再穷举已不使用的 wrapper/export/组合协议 |

`agent_config.go` 的 `SelectorRule.validate/cr` 与 `agent_associations.go` 的共用匹配逻辑，是 selector 合并的代码依据。四种资源的实际 REST 接线仍各验证一次。若实施时发现某个组合走独立业务分支，就不能称为“等价”直接删掉，须补入相应 case 的输入表。

## CI 如何执行

| CI job | 拟执行内容 | 失败标准 |
| --- | --- | --- |
| UT | 构建/生成检查、18 个 Ginkgo UT、race、产品语句覆盖率 ≥70%；前端只做类型检查与构建 | 任一用例失败/漏跑、race、覆盖率不足或构建不通过，job 失败 |
| E2E | 自动创建两套 kind，部署固定依赖和平台，跑全部 10 个 Ginkgo E2E，保存失败日志/截图后清理 | 环境失败、任一必要步骤失败/未执行、清理失败均阻断；10 个全部通过才算 E2E 通过 |

本轮取消对外的 Q/K/B、CI_FAST/CI_SMOKE/LOCAL_FULL 与 supplemental 分组，只保留 UT 和 E2E 两种测试类型；同仓 PR 和 main 运行同一套 18+10 清单，不再维护另一套 Smoke 子集。私有 Operator 源码仍只提供给可信同仓 job；拿不到必要依赖时不能伪造 E2E 通过。

提供 `make ut`、`make e2e` 两个主入口。`make e2e` 自带环境生命周期；常规本地/CI 不要求先手工造环境 JSON。保留 candidate SHA、场景 ID、请求/操作关联信息、Ginkgo 报告、失败诊断及本 run 资源身份，移除只为旧 profile 矩阵服务的重复计数和多层包装。原始进程输出、kubeconfig 和认证材料仍留在私有目录；CI artifact 只包含可公开的场景报告、脱敏失败诊断和截图。

进入实施时再同步修改旧规格、固定目录、校验器和 Issue 测试计划；新 case 的 `By` 步骤继续写中文说明。方案实施完应回读实际 Ginkgo 场景数并与本文核对；不能只改清单数字，也不能用本稿代替真实执行记录。
