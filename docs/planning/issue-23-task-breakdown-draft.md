## 拆分原则

- 每项交付均贯穿持久化、类型化接口、页面和行为验收，能够独立演示或验证。
- ③先让现有组件操作具备逐资源进度和安全恢复，作为④管理第二份 CR 的前置；③本身仍可用既有单资源操作验收。
- 每项自行完成相关自动化、真实集群或浏览器验证；不设置一个末尾任务来补写全部测试。
- 以下“阻塞于”仅列直接依赖；六项均已关联父规格 #23，并使用原生阻塞关系及 ready-for-agent 标签。

## ① 实例创建身份与管理员实例写保护

**阻塞于：** 无。

**交付行为：** 新建 exporter、collector 实例展示固定创建用户和创建时角色；普通用户可查看但不能变更管理员创建的实例。角色变化、直接 RPC 和后台任务均不能绕过保护。

**验收要求：**

- 服务端从实际认证身份固定创建用户及当时角色，不接受客户端冒充或后续覆盖。
- 实例列表、详情及类型化接口展示创建关系、可管理性和只读原因。
- 普通用户对管理员创建实例的草稿编辑、草稿删除、下发、运行状态调整、实例删除、重试、继续和取消均被禁止；非管理员创建实例沿用既有集群授权。
- 当前管理员管理能力、原有外部实例只读边界和集群访问限制保持一致。
- 创建者降级后，其管理员身份创建的实例仍受保护；普通用户升级不改写旧创建身份。
- 后台每次实际写入前复核当前权限；已发请求失权后只读核验。
- 扩展历史 schema 时，角色未知实例先对普通用户只读，不用当前账号角色补造历史。
- 新增 Ginkgo 行为测试覆盖公开 HTTP、直接 RPC、受理后派发前角色变化；浏览器验证可编辑与只读的明确区别。

**独立演示：** 在同一集群中由管理员、普通用户各创建一个实例，用普通用户打开两者并尝试页面、HTTP、RPC 变更，核对允许与拒绝结果。

## ② 历史实例创建用户补齐与管理权限确认

**阻塞于：** ①。

**交付行为：** 升级后可看到可靠追溯的历史创建用户；角色未知实例默认只读，管理员可以明确确认其管理权限，且不会改写历史事实。

**验收要求：**

- 仅使用能与原实例唯一对应的创建记录补齐 user ID；记录缺失、矛盾时保持未知。
- 不用集群所属用户、首次发布者或账号当前角色推测创建身份。
- 创建时角色未知的实例默认禁止普通用户变更，页面解释原因。
- 提供类型化管理员权限确认入口及页面交互，保存确认用户、时间和确认结果；普通用户不能执行该确认。
- 管理权限确认不伪造历史角色，不补造未知创建用户，也不改变已知管理员创建实例的保护规则。
- 保留原实例、版本、任务、UID、密文和审计关系，迁移失败可恢复原数据库。
- 通过公开行为及独立旧 schema 夹具验证迁移、未知、冲突和确认后的权限；浏览器验证管理员确认与普通用户只读状态。

**独立演示：** 对带有完整与不完整创建证据的旧数据库升级，检查创建用户及未知角色；由管理员确认一条历史未知实例的管理权限，再以普通用户核对实际可管理范围。

## ③ 逐资源操作进度与安全恢复

**阻塞于：** 无。

**交付行为：** 现有 KSM、Agent 发布与删除操作能够展示、保存和恢复每份受管资源的状态；升级后的旧任务仍执行原冻结语义。

**验收要求：**

- 操作与版本可以表达逐资源的冻结目标、有效配置、已确认 UID、可能已发送标记及执行结果；不以单个操作级标记代替全部资源身份。
- 现有单资源发布、删除、人工重试、继续和取消在新模型上仍可通过公开入口完成，页面展示具体资源进度。
- 已确认的资源身份与结果独立持久化，后续步骤失败或 Pod 重建不丢失前序进度。
- 恢复只核验原身份和原冻结配置，不采用当前草稿、新映射默认值或同名替代 UID。
- 首次创建无已确认 UID 时保持身份无法确认，不能凭配置或标签补认。
- 已有操作和旧 schema 迁移不新增资源写入，不因升级自动重放；删除、存储及未知结果保护继续有效。
- 每个实际写入沿用统一授权边界；与①合并时覆盖逐资源的写前实例保护。
- Ginkgo 验证公开 HTTP/真实 RPC/SQLite 链路、响应丢失、重启及新旧 schema 兼容；操作页面验证分步骤状态。

**独立演示：** 对既有单 CR 操作注入响应丢失和平台重启，查看逐资源进度及真实请求次数，证明恢复没有多发写请求。

## ④ 新 exporter 配套 ServiceMonitor 全生命周期

**阻塞于：** ①、③。

**交付行为：** 新建 exporter 在明确下发时自动配套一个带创建用户标签的 ServiceMonitor；更新、删除、部分失败和人工补齐均可端到端完成。

**验收要求：**

- 保存草稿不写集群；发布预览和冻结版本包含 exporter 与配套 ServiceMonitor 的有效配置及影响。
- 由平台生成位于指标 Service 所在部署 namespace 的稳定命名 ServiceMonitor，并写入 monitor-mgr.io/user-id。
- 复用 Operator 已生成的 Service，按实际稳定标签和正确命名指标端口选择本实例；覆盖现有 KSM 合法部署模式及名称规范化，不向 Operator Service 添加 user 标签。
- 发布前核验 CRD、目标 namespace、必要权限和同名冲突；不接管外部或同名资源。
- 一个实例更新、删除不影响其他实例；配套资源独立校验 UID 和漂移，删除完成须确认整体清理。
- exporter 成功而 ServiceMonitor 失败时保留 exporter，显示部分进度；人工重试固定原版本并先核验，仅补齐必要步骤。
- 分别覆盖第二资源写入失败、响应丢失、未知 UID、平台重启和写前失权，不凭标签认领资源。
- 页面展示配套配置及操作结果；相关 Ginkgo 行为测试、真实集群生命周期和浏览器状态验证随本项完成。

**独立演示：** 创建两个新 exporter，发布后回读各自配套 ServiceMonitor；使其中一个的 ServiceMonitor 步骤失败后人工补齐，再更新、删除该实例并确认另一实例不变。

## ⑤ 历史 exporter 的显式补建与旧发布边界

**阻塞于：** ②、④。

**交付行为：** 历史 exporter 升级后保持集群现状，用户下一次明确发布时才补建配套 ServiceMonitor；旧版本与在途任务保持原冻结目标。

**验收要求：**

- 平台升级、历史创建者补齐、管理员权限确认以及状态轮询均不自动写入 ServiceMonitor。
- 已有 exporter UID 保持原管理关系；下一次明确发布将配套 ServiceMonitor 纳入新冻结版本，不能把旧 exporter 当作新资源重复创建。
- 创建用户已知时使用其原 user ID；未知时明确阻止依赖身份的配套发布，不回退为当前用户或集群所属用户。
- 旧冻结版本、旧操作和其重试/恢复不被追溯追加 ServiceMonitor；新显式发布与旧操作版本保持区分。
- 补建遇到同名外部资源、原 exporter UID 替换、漂移、缺权限或响应丢失时沿用身份与恢复保护。
- 浏览器能展示补建前后配置与操作差异；Ginkgo 和真实集群验证升级无写入、显式发布补建及失败恢复。

**独立演示：** 升级一个仅有 KSM CR 的历史实例，先证明集群没有新增写入，再由有权用户明确发布并回读 ServiceMonitor；同时验证旧操作恢复不会触发补建。

## ⑥ Agent 按创建用户关联与实际采集闭环

**阻塞于：** ②、④。

**交付行为：** 用户在 Agent 中选择按用户关联 exporter，默认使用 Agent 创建用户；经过预览、发布后，在真实集群中采到对应 exporter 指标。

**验收要求：**

- 快捷选项默认取 Agent 实例创建用户，展示具体目标用户，固定到明确配置；管理员编辑不会改成当前登录用户。
- 保留既有不关联默认值、自定义标签规则及匹配预览，不把快捷选项变成强制全选。
- object selector 与 namespace 发现范围分别配置；预览区分零匹配、读取失败和权限不足。
- 已可靠补齐创建用户的历史 Agent 可以使用快捷选项；创建者未知时明确说明无法使用，不替换为其他身份。
- 用户分组不能代替实例授权；普通用户不能通过关联入口修改管理员创建的 Agent。
- 在已有 namespace 范围和权限满足时，新建相同创建用户的 exporter 可被既有 Agent 规则动态发现。
- Ginkgo 覆盖固定 user ID、管理员编辑、自定义规则和跨 namespace；浏览器验证完整关联操作。
- 真实集群读取 Agent 实际采用的配套配置，并取得与本例 exporter 对应的实际指标样本；匹配列表、CR Ready 或配置生成不能替代采集证据。
- 将本项涉及的端到端用例纳入现有验收执行与证据校验入口；其他切片的行为测试仍由各自负责。

**独立演示：** 管理员和普通用户在同一集群各创建 exporter、Agent；分别选择快捷关联，回读选择结果并取得各目标的实际指标样本；再由管理员编辑用户 Agent，验证关联 user ID 未被静默改写。

## 共通实施与验收要求

- 每个实现 Issue 在编码前领取并回读，按仓库约定发布五列用例评论并回读，同时保存本地副本；方案草案不替代实施前计划。
- 新增 Go UT、E2E 使用 Ginkgo，UT 覆盖率至少 70%；复用公开 HTTP → 真实 Kitex RPC → SQLite 的主要行为入口，辅以直接 RPC、受控目标及实际集群。
- 重复命令维护在 Makefile，部署保持 Helm，关键授权、条件写入、未知结果及恢复边界添加中文注释。
- 每个切片分别给出本地自动化、适用的真实集群与浏览器结果；证据绑定 testedCommit，失败、未执行和环境失败分别报告。
- 本拆分不创建新的独立采集配置 CRUD 产品入口，也不修改现有平台与 Operator 的责任分界。
