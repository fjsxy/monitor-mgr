## 父规格

[fjsxy/monitor-mgr#23 exporter 配套 ServiceMonitor、实例创建归属与管理员实例保护规格](https://github.com/fjsxy/monitor-mgr/issues/23)。

## 直接依赖

无；本任务可先行完成身份与权限能力，不等待 Operator 发布。

## 交付行为

新建 exporter、collector 实例展示固定创建用户和创建时角色；普通用户可查看但不能变更管理员创建的实例。角色变化、直接 RPC 和后台任务均不能绕过保护。

## 验收标准

- [ ] 服务端从实际认证身份固定创建用户及当时角色，不接受客户端冒充或后续覆盖。
- [ ] 实例列表、详情及类型化接口展示创建关系、可管理性和只读原因。
- [ ] 普通用户对管理员创建实例的草稿编辑、草稿删除、下发、运行状态调整、实例删除、重试、继续和取消均被禁止；非管理员创建实例沿用既有集群授权。
- [ ] 当前管理员管理能力、原有外部实例只读边界和集群访问限制保持一致。
- [ ] 创建者降级后，其管理员身份创建的实例仍受保护；普通用户升级不改写旧创建身份。
- [ ] 后台每次实际写入前复核当前权限；已发请求失权后只读核验。
- [ ] 扩展历史 schema 时，角色未知实例先对普通用户只读，不用当前账号角色补造历史。
- [ ] 新增 Ginkgo 行为测试覆盖公开 HTTP、直接 RPC、受理后派发前角色变化；浏览器验证可编辑与只读的明确区别。

- [ ] 新增采集开关、参数和归属标签入口同样服从既有身份保护；客户端不能冒充或覆盖创建用户，平台只从固定身份向 exporter CR 投影标签。
- [ ] 平台受理及每次实际写 exporter CR 前复核权限；撤权后不发出新的平台写入。Operator 对已发布期望态的持续调谐不被当作平台越权，也不引入 Operator 账号/角色判断。
- [ ] 用受控 API 分别验证 HTTP、直接 RPC 和 worker 的允许/拒绝结果；新模式没有平台 SM 写请求。对依赖新契约的入口在 #28 集成后补齐联合回归，本任务身份能力本身不依赖 Operator 发布。

## 独立演示

在同一集群中由管理员、普通用户各创建一个实例，用普通用户打开两者并尝试页面、HTTP、RPC 变更，核对允许与拒绝结果。

## 实施与验收约束

- 本轮只同步任务范围，不领取、不编码。开始或恢复实现前，回读父规格、依赖及评论，按 `docs/agents/implementation.md` 发布并回读五列用例计划，同步本地 `docs/e2e/issue-<编号>.md`；既有稳定 ID 保留，变化的输入和预期先修订再实现。
- Go UT/E2E 使用 Ginkgo，UT 覆盖率至少 70%；主要行为入口为公开 HTTP → 真实 Kitex RPC → SQLite → worker，必要时补直接 RPC、受控 TLS Kubernetes 目标、真实集群和浏览器。
- 每项自行交付对应测试，不把测试集中留给 #30。Makefile 固化重复命令，部署使用 Helm；关键授权、UID/RV 条件写、发送边界和恢复禁重放添加中文注释。
- 证据分别记录本地测试、真实集群、浏览器、远端 CI、清理和 testedCommit；旧 PR #31 的绿色结果不能替代新边界验收。
- 不创建独立采集配置 CRUD 产品入口；平台不直接 create/update/patch/delete 配套 ServiceMonitor，不复制 Operator 的 Service 规则，不把 user 标签用作授权依据。
