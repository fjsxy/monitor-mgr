## 交付行为

升级后可看到可靠追溯的历史创建用户；角色未知实例默认只读，管理员可以明确确认其管理权限，且不会改写历史事实。

## 验收标准

- [ ] 仅使用能与原实例唯一对应的创建记录补齐 user ID；记录缺失、矛盾时保持未知。
- [ ] 不用集群所属用户、首次发布者或账号当前角色推测创建身份。
- [ ] 创建时角色未知的实例默认禁止普通用户变更，页面解释原因。
- [ ] 提供类型化管理员权限确认入口及页面交互，保存确认用户、时间和确认结果；普通用户不能执行该确认。
- [ ] 管理权限确认不伪造历史角色，不补造未知创建用户，也不改变已知管理员创建实例的保护规则。
- [ ] 保留原实例、版本、任务、UID、密文和审计关系，迁移失败可恢复原数据库。
- [ ] 通过公开行为及独立旧 schema 夹具验证迁移、未知、冲突和确认后的权限；浏览器验证管理员确认与普通用户只读状态。

- [ ] 历史身份补齐、管理员权限确认、平台/Operator 升级及状态轮询均不启用配套采集，不产生 ServiceMonitor 写入或为旧 CR 自动加新字段。
- [ ] 创建用户未知时，阻止依赖 user 标签的新采集发布及快捷关联，不以当前操作者或集群所属用户代替；原有自定义 selector 仍遵守其校验与授权。
- [ ] 为 #29 提供可靠创建关系及权限确认结果；只恢复事实，不接管旧 ServiceMonitor，不改冻结版本、UID 或历史操作。

## 独立演示

对带有完整与不完整创建证据的旧数据库升级，检查创建用户及未知角色；由管理员确认一条历史未知实例的管理权限，再以普通用户核对实际可管理范围。

## 实施与验收约束

- 本轮只同步任务范围，不领取、不编码。开始或恢复实现前，回读父规格、依赖及评论，按 `docs/agents/implementation.md` 发布并回读五列用例计划，同步本地 `docs/e2e/issue-<编号>.md`；既有稳定 ID 保留，变化的输入和预期先修订再实现。
- Go UT/E2E 使用 Ginkgo，UT 覆盖率至少 70%；主要行为入口为公开 HTTP → 真实 Kitex RPC → SQLite → worker，必要时补直接 RPC、受控 TLS Kubernetes 目标、真实集群和浏览器。
- 每项自行交付对应测试，不把测试集中留给 #30。Makefile 固化重复命令，部署使用 Helm；关键授权、UID/RV 条件写、发送边界和恢复禁重放添加中文注释。
- 证据分别记录本地测试、真实集群、浏览器、远端 CI、清理和 testedCommit；旧 PR #31 的绿色结果不能替代新边界验收。
- 不创建独立采集配置 CRUD 产品入口；平台不直接 create/update/patch/delete 配套 ServiceMonitor，不复制 Operator 的 Service 规则，不把 user 标签用作授权依据。
