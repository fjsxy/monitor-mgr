## 验收标准

- [ ] 保留旧实例、版本、操作、逐资源进度、已确认 UID、可能已发送标记及执行结果；不用单个状态覆盖历史子资源事实，不删表清历史或重置 UID。
- [ ] 既有单 CR 发布、删除、人工重试、继续和取消保留原冻结目标；恢复不采用当前草稿、新默认值、重命名/新 targetNamespace 或同名替代 UID。
- [ ] 首次创建响应丢失且 UID 未确认时，维持身份无法确认和变更保护；超时、重启均不能靠 spec 或 labels 认领。
- [ ] 旧方案冻结的 ServiceMonitor 未完成步骤在切换后只读核验并显式待处理，自动派发、重试、继续和重启恢复都不得续写；已发送的真实结果要保留，不能假记成功、撤销历史或转成新模式。
- [ ] 新模式的资源步骤派发只接受实际平台写入的 exporter/Agent CR，ServiceMonitor 作为只读观察对象；具体采集字段与读模型由 #28 集成。
- [ ] 受理及实际写前授权、UID/RV 条件写、已发送请求失权只核验、删除与存储保护继续有效；Operator 的声明式重试不触发平台补写。
- [ ] 操作页面区分 CR 写入结果、历史待处理步骤和观察状态，不将 Operator 子对象故障伪装成可重试的第二份平台 CR。
- [ ] 通过独立旧 schema/旧任务夹具、真实 Kitex/SQLite 重启、受控 API 请求计数验证所有恢复入口不写 SM；不只改 schema 版本号或直接插表替代用户主流程。

## 独立演示

注入一次 CR 创建响应丢失并重启平台，证明未认领、未重复写；加载带 SM 可能已发送步骤的旧任务，再次执行重试/继续/恢复，只读核验并显示待处理。

## 实施与验收约束

- 本轮只同步任务范围，不领取、不编码。开始或恢复实现前，回读父规格、依赖及评论，按 `docs/agents/implementation.md` 发布并回读五列用例计划，同步本地 `docs/e2e/issue-<编号>.md`；既有稳定 ID 保留，变化的输入和预期先修订再实现。
- Go UT/E2E 使用 Ginkgo，UT 覆盖率至少 70%；主要行为入口为公开 HTTP → 真实 Kitex RPC → SQLite → worker，必要时补直接 RPC、受控 TLS Kubernetes 目标、真实集群和浏览器。
- 每项自行交付对应测试，不把测试集中留给 #30。Makefile 固化重复命令，部署使用 Helm；关键授权、UID/RV 条件写、发送边界和恢复禁重放添加中文注释。
- 证据分别记录本地测试、真实集群、浏览器、远端 CI、清理和 testedCommit；旧 PR #31 的绿色结果不能替代新边界验收。
- 不创建独立采集配置 CRUD 产品入口；平台不直接 create/update/patch/delete 配套 ServiceMonitor，不复制 Operator 的 Service 规则，不把 user 标签用作授权依据。
